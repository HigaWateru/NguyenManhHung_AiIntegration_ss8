# Bài 4 - CRM Chat API với QuestionAnswerAdvisor

Project độc lập triển khai `POST /api/v1/crm/chat` bằng Spring AI `ChatClient` và `QuestionAnswerAdvisor`.

## Controller

File chính: `src/main/java/demo/crm/controller/CrmChatController.java`.

```java
@RestController
@RequestMapping("/api/v1/crm")
public class CrmChatController {
    private final ChatClient chatClient;

    @PostMapping("/chat")
    public ResponseEntity<ChatResponse> chat(@Valid @RequestBody ChatRequest request) {
        try {
            String answer = chatClient.prompt()
                .user(request.message())
                .call()
                .content();
            return ResponseEntity.ok(new ChatResponse(answer));
        } catch (RuntimeException exception) {
            return ResponseEntity.status(HttpStatus.SERVICE_UNAVAILABLE)
                .body(new ChatResponse("Dịch vụ trợ lý CRM tạm thời không khả dụng. Vui lòng thử lại sau."));
        }
    }
}
```

## Cấu hình RAG

`AiChatConfig` tạo `QuestionAnswerAdvisor` với `VectorStore`, sau đó đăng ký advisor mặc định trên `ChatClient`:

```java
@Bean
public ChatClient crmChatClient(ChatClient.Builder builder, VectorStore vectorStore) {
    QuestionAnswerAdvisor advisor = QuestionAnswerAdvisor.builder(vectorStore).build();
    return builder
        .defaultSystem(GROUNDING_PROMPT)
        .defaultAdvisors(advisor)
        .build();
}
```

Khi controller gọi `chatClient.prompt()`, advisor tự thực hiện similarity search, đưa các document phù hợp vào prompt, rồi mới để LLM sinh câu trả lời. Controller không cần tự ghép context. Grounding prompt yêu cầu trợ lý chỉ dùng CONTEXT, không suy đoán hoặc bịa thông tin; nếu context thiếu thì phải nói rõ.

## CORS an toàn

`CorsConfig` chỉ cho phép origin cấu hình bằng `CRM_ALLOWED_ORIGIN`, mặc định `http://localhost:3000`. API chỉ mở `POST` và `OPTIONS`, giới hạn headers cần thiết, không dùng wildcard `*` và tắt credentials. Khi triển khai production, đặt origin frontend cụ thể:

```powershell
$env:CRM_ALLOWED_ORIGIN = "https://crm.example.com"
```

## Gọi API

```powershell
curl.exe -X POST "http://localhost:8080/api/v1/crm/chat" `
  -H "Content-Type: application/json" `
  -d '{"message":"Chính sách đổi trả trong bao lâu?"}'
```

Response thành công:

```json
{"answer":"... câu trả lời dựa trên tài liệu CRM ..."}
```

VectorStore hoặc LLM bị gián đoạn sẽ trả HTTP `503 Service Unavailable`, không để exception rò ra client.

## Minh chứng console

Khi Ollama và pgvector hoạt động, log có thể hiện luồng query, context do advisor lấy và câu trả lời:

```text
INFO ...CrmChatController : CRM query received: Chính sách đổi trả trong bao lâu?
INFO ...QuestionAnswerAdvisor : Retrieved 3 documents from VectorStore and added context to prompt
INFO ...CrmChatController : CRM answer generated by LLM with context supplied by QuestionAnswerAdvisor: Khách hàng có thể đổi trả trong vòng 30 ngày...
```

Test tự động đã kiểm tra nhánh lỗi kết nối:

```text
INFO ...CrmChatController : CRM query received: Chính sách đổi trả là gì?
ERROR ...CrmChatController : CRM chat failed because VectorStore or LLM is unavailable
BUILD SUCCESSFUL
```

## Chạy project

Project có Gradle wrapper riêng:

```powershell
.\gradlew.bat test
.\gradlew.bat bootRun
```

Cần cấu hình Ollama model `llama3.2` và `nomic-embed-text`; pgvector datasource cần được bổ sung theo môi trường Supabase thực tế trước khi chạy production.
